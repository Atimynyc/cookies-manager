Cookie Controller - Chrome Web Store 审核说明（中文版）

单一用途说明

Cookie Controller 的唯一用途是在用户明确选择的网页上查看和管理站点数据，包括 Cookie、Local Storage 和 Session Storage。搜索、复制、批量修改、导入导出、值格式化、站点状态、修改历史和撤销功能均直接服务于这一用途。插件不提供广告、统计分析、用户跟踪或与站点数据管理无关的功能。

需请求 cookies 的理由

插件需要使用 chrome.cookies API 读取用户所选网站的 Cookie，获取当前标签页对应的 Cookie Store，并执行新增、修改、删除和变更监听操作。这是插件查看和管理 Cookie 这一核心功能所必需的。Cookie 数据只在用户打开并操作插件时于本地处理，不会上传或共享给开发者或第三方服务器。

需请求 tabs 的理由

插件需要使用 chrome.tabs API 识别当前活动标签页、读取当前窗口中的 HTTP/HTTPS 标签页列表、在用户选择后切换标签页、获取标签页所属窗口，以及在用户启用自动刷新后重新加载页面。这些操作用于确定和切换站点数据的管理目标。插件不会使用该权限建立浏览历史、分析用户访问行为或向外部服务器发送标签页信息。

需请求 storage 的理由

插件需要使用 chrome.storage.local 在用户设备上保存界面偏好、自动刷新设置、列宽、值工具模式、收藏的站点数据标识、站点数据读取确认记录、用户主动创建的站点状态和最近修改记录。收藏标识不包含 Cookie 或存储值。chrome.storage.session 仅在当前浏览器会话中保存差异查看和批次撤销所需的完整前后值。以上数据仅用于恢复插件状态和支持站点数据管理工作流，不会同步或上传到开发者或第三方服务器。用户可以通过清除扩展数据或卸载插件删除这些本地数据。

需请求 scripting 的理由

插件在 src/shared/storage-api.js 中直接调用 chrome.scripting.executeScript，在用户所选标签页执行随扩展包发布的 operateStorageInPage 函数，以读取、添加、修改和删除该页面的 Local Storage 与 Session Storage 数据。复现方式：批准站点访问权限，点击 Local 或 Session，再通过 Import > Quick entry 新增数据，或编辑已有条目。注入操作只在用户打开插件并执行相关操作时发生。插件不下载、不生成也不执行任何远程代码。

需请求 sidePanel 的理由

插件需要使用 chrome.sidePanel API 在 Chrome 侧边栏中打开同一套站点数据管理界面，让用户在浏览网页的同时持续查看和管理 Cookie、Local Storage 与 Session Storage。该权限只用于创建和打开插件侧边栏，不用于修改其他浏览器界面或收集额外数据。

需请求主机权限的理由

插件声明 http://*/* 和 https://*/* 为可选主机权限。默认逐站申请访问权限；Cookie 读取包括所选主机及各级父域主机的 HTTP、HTTPS 权限。用户可以在设置或站点授权弹框中主动开启“允许所有网站”，授权读取所访问的所有 HTTP/HTTPS 网站的 Cookie、Local Storage 和 Session Storage。关闭开关会撤销通配主机权限并恢复逐站授权。chrome.cookies API 访问 Cookie 以及 chrome.scripting.executeScript 访问网页存储都要求具备与目标网站匹配的主机权限。数据仍在用户打开和操作插件时按所选页面读取，插件不会在后台批量扫描网站，数据不会传输到外部服务器。

远程代码声明

插件不使用远程代码。所有 JavaScript 均包含在上传至 Chrome Web Store 的扩展包内，不从网络下载脚本，也不通过 eval 或其他方式执行远程提供的代码。
