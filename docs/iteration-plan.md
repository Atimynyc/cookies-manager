## 1. 迭代背景

当前版本已经完成 Cookie、Local Storage、Session Storage 的查看、搜索、编辑、删除、批量操作、单条导入、全量导出、值处理工具、配置组、最近修改记录、撤销、自动刷新和 Side Panel 等基础能力。

后续迭代不再以增加零散操作按钮为主，而是把产品从“单条站点数据编辑器”升级为“可保存、可比较、可迁移、可回滚的站点状态工作台”，重点服务开发、测试和联调场景中的账号切换、环境切换、灰度配置和问题复现。

## 2. 总体目标

### 2.1 产品目标

- 支持一次处理多条 Cookie 和 Web Storage 数据。
- 支持保存并重复应用完整的站点状态配置。
- 支持比较不同站点、标签页或快照之间的差异。
- 在批量修改和跨环境迁移时提供预览、校验和回滚能力。
- 降低敏感数据误展示、误复制和误导出的风险。
- 保持所有数据仅在用户本机处理，不引入账号、服务端或遥测系统。

### 2.2 体验目标

- 常用操作在 Popup 中保持轻量，复杂操作优先在 Side Panel 中完成。
- 写入前展示将要发生的变化，危险操作必须明确确认。
- 批量操作应以一个事务展示结果，并支持整批撤销。
- Cookie、Local Storage、Session Storage 使用统一的选择、预览、应用和历史交互。
- 默认界面保持简洁，高级 Cookie 属性和迁移策略按需展开。

### 2.3 工程目标

- 保持 Manifest V3 和原生 ES Module，不因本轮迭代强制引入框架或构建工具。
- 拆分当前集中在 `popup.js` 中的状态、业务操作和视图逻辑。
- 为数据格式、差异计算、冲突处理和批量事务补充单元测试。
- 保留现有 Playwright 验收测试，并覆盖新增的关键用户流程。

## 4. v0.2.1：迭代基础

实现状态：已完成基础交付，保留模块拆分技术债。共享层已覆盖 Chrome API、数据格式、项目标识、批量执行与结果、历史、配置组和持久化；Popup 已拆出多个视图与服务模块。后续新增对比、迁移和事务历史时，应继续缩小 `popup.js` 与 `popup-workbench.js` 的职责，而不是继续向两个文件集中逻辑。

### 4.1 目标

在不改变现有用户行为的前提下，降低后续批量操作、配置组和差异对比的实现风险。

### 4.2 功能与工程任务

1. 拆分 Popup 逻辑：
   - 数据加载与站点切换。
   - Cookie 操作。
   - Storage 操作。
   - 配置组存储。
   - 历史和撤销。
   - Dialog 与状态提示。
   - 表格和详情视图渲染。
2. 定义统一的站点数据项标识：
   - Cookie：`storeId + partitionKey + domain + path + name`。
   - Storage：`type + origin + key`。
3. 定义统一的批量操作结果：
   - `success`：成功项目。
   - `failed`：失败项目及 Chrome API 原始错误。
   - `skipped`：因冲突策略或校验被跳过的项目。
4. 定义站点数据包 v1 协议，并提供解析、校验和版本兼容入口。
5. 为以下纯逻辑补充单元测试：
   - `name=value` 解析。
   - Cookie 和 Storage 序列化。
   - 数据包校验。
   - 项目标识和冲突判断。
   - 最近修改记录规范化。
6. 更新 Manifest 简介，使其与 Cookie 和 Web Storage 的实际能力一致。

### 4.3 验收标准

- 现有 `npm run test:acceptance` 全部通过。
- Popup 和 Side Panel 的现有功能及布局无行为回归。
- 新增单元测试可通过统一的 `npm test` 命令执行。
- 业务模块不直接操作无关 DOM，视图模块不直接调用 Chrome 写入 API。
- 数据包解析失败时只返回错误，不修改任何站点数据。

## 5. v0.3.0：数据包与配置组

实现状态：已完成 JSON 数据包与 Cookie 专用 Netscape/cURL 格式的导入导出、差异预览、冲突策略、配置组、应用时变量、批量结果与会话内整批撤销。Import、Export 和 Profiles 作为表格工具栏的三个独立入口接入 Popup 和 Side Panel，避免重复的 Site Data 二级入口。对应协议文档、单元测试、Playwright 验收流程和截图产物已纳入仓库。

### 5.1 目标

解决当前“可以全量导出，但只能单条导入”的不对称问题，并支持保存和重复应用一组站点状态。

### 5.2 站点数据包

主格式采用带版本号的 JSON：

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-08-11T10:00:00.000Z",
  "source": {
    "url": "https://uat.example.com/page",
    "origin": "https://uat.example.com"
  },
  "data": {
    "cookies": [],
    "localStorage": [],
    "sessionStorage": []
  }
}
```

要求：

- 保留 Cookie 的 domain、path、expirationDate、sameSite、secure、httpOnly、storeId 和 partitionKey 等可用属性。
- Storage 的 key 和 value 始终按字符串保存。
- 未知字段应忽略，未知 `schemaVersion` 应拒绝导入并给出明确提示。
- 导出范围支持当前视图、选中项目和全部三类数据。
- 支持复制到剪贴板和保存为 `.json` 文件。
- UI 导出的 JSON 在 v1 数据包之外保留顶层 `url`、`host`、`type` 和 `count` 兼容字段。
- Cookie 额外支持七列 Netscape/cURL cookie jar 的导入导出、`#HttpOnly_` 和会话 Cookie；该格式不表示 SameSite、Partitioned/CHIPS、Cookie store 或两类 Storage。
- Import 入口内提供快速输入、JSON 数据包和 Netscape/cURL 三种方式；Cookie 快速输入使用独立 Name/Value 输入框并可动态增加多行，Storage 继续保留单条 `key=value` 入口。

### 5.3 批量导入流程

流程固定为：

1. 选择文件或粘贴文本。
2. 解析并校验数据包。
3. 读取当前目标站点状态。
4. 展示新增、修改、相同、冲突和不支持项目。
5. 用户选择项目和冲突策略。
6. 保存操作前快照。
7. 执行写入并展示逐项结果。
8. 根据设置刷新页面。

冲突策略：

- `覆盖`：使用导入值替换当前值。
- `跳过`：保留当前值。
- `仅新增`：只写入目标中不存在的项目。
- `逐项选择`：用户为每个冲突单独决定。

默认不删除目标中额外存在的数据。删除缺失项属于后续的“完全同步”高级模式。

### 5.4 配置组

配置组是可重复应用的数据包，至少包含：

- 名称、说明、标签和创建时间。
- 来源站点和适用域名规则。
- 选中的 Cookie、Local Storage、Session Storage 项目。
- 应用时的默认冲突策略。
- 可选变量，例如 `${userId}`、`${grayFlag}`。

第一版配置组规则：

- 只保存在 `chrome.storage.local`，不使用同步存储。
- 应用前始终展示差异预览。
- 默认只允许应用到相同 origin。
- 跨域应用必须由用户明确选择目标映射。
- 敏感变量可配置为“应用时输入”，输入值不写入配置组。

### 5.5 验收标准

- Cookie、Local Storage、Session Storage 均可完成导出后再导入的往返操作。
- Netscape/cURL Cookie 文件可完成导出、自动识别、预览、写入和整批撤销，并明确提示无法表示的高级属性。
- 同名但 domain、path 或 partitionKey 不同的 Cookie 不会互相覆盖。
- 无效 JSON、未知协议版本和缺少必需字段时不会修改目标站点。
- 导入 100 个项目时界面保持可响应，并展示执行进度。
- 部分写入失败时能精确显示失败项目和原因。
- 用户可通过导入前快照撤销本次批量操作。
- 配置组可创建、重命名、复制、删除、导出和应用。
- 所有数据处理均在本地完成，不产生外部网络请求。

## 6. v0.3.1：界面收敛与操作分层

实现状态：已完成。本版本只调整信息架构、视觉层级和操作呈现，不改变现有数据模型、导入导出协议及写入行为。Popup 与 Side Panel 均保留直接可见的 Import、Export 和 Saved States，批量操作仅在选择项目后显示；420px Side Panel 已补充响应式布局与自动化验收。

### 6.1 目标

- 保留现有“数据列表 + 详情编辑器”双栏结构和紧凑工具型视觉风格。
- 简洁以“减少用户判断”为目标，不以隐藏核心功能或减少按钮数量为目标。
- Import 和 Export 在 Popup 与 Side Panel 中始终直接可见，一次点击进入对应流程。
- 将全局操作、当前项目操作和批量操作放在各自上下文中，避免不同作用域的按钮混在同一组。
- 收敛配置组、快照和历史等相近概念，移除低频且与现有能力重叠的 Value 模板界面，暂不增加新的独立快照类型。

### 6.2 操作分层

始终可见的全局操作：

- Cookie、Local Storage、Session Storage 切换。
- 搜索、Import、Export 和刷新。
- Saved States 保持可发现，但视觉权重低于 Import 和 Export。

按上下文展示的操作：

- 选中列表项目后显示批量 Set value 和 Delete；未选中时不占用操作位置。
- 打开单项详情后显示 Copy、Favorite、Delete 和 Save。
- 只有编辑内容发生变化时才强调并启用 Save。
- 批量导入或应用完成后才显示对应 Undo。

低频管理操作：

- 清空历史、重置列宽、帮助和高级设置后续统一收入次级入口。
- History 和 Side Panel 保持顶部次级入口，不与当前编辑的主操作争夺视觉权重。

### 6.3 页面布局

- 表格上方设置独立的全局操作区，直接展示 Import、Export 和 Saved States。
- 表格底部只保留选择摘要和批量操作，批量按钮根据选择状态出现。
- Side Panel 已打开时隐藏重复的 Side Panel 入口，并将刷新控件固定在顶部右侧。
- 收藏状态使用插件自身的 Cookie 图标，未收藏时弱化显示，收藏后恢复品牌色。
- 详情页不再显示 Save template / Apply template，也不提供模板管理入口；升级时保留已有本地模板数据，不主动清除。
- Import、Export 的复杂步骤继续使用现有大 Dialog；Side Panel 提供更大空间，但不作为寻找功能的前置步骤。
- Popup 优先展示 Name、Value、Expires/Type 和 Flags；完整作用域与高级属性继续在详情区展示，列裁剪需结合现有可调整列宽能力逐步验证。
- 编辑器按照 Name/作用域、Value、过期时间、操作按钮、其他属性的顺序保持清晰层级。

### 6.4 概念命名

- `Saved States`：一组可重复应用的 Cookie 和 Storage 数据，对应现有 Profiles 能力。
- `History`：修改记录与会话内撤销。
- v0.3.1 不新增独立 Snapshot；后续比较能力优先扩展 Saved States。

### 6.5 验收标准

- Popup 与 Side Panel 均能直接看到并点击 Import 和 Export。
- Import、Export 和 Saved States 与批量编辑、批量删除在视觉和 DOM 分组上明确分离。
- 未选择项目时不显示批量操作；选择一个或多个项目后显示数量和可用操作。
- 单项 Save 仅在值或过期时间发生变化时启用并成为编辑区主操作。
- 用户可见的 Profiles 名称统一为 Saved States，内部存储格式保持兼容。
- 现有单元测试和导入、导出、Saved States、历史、编辑、批量操作验收流程无行为回归。
- Popup 和 Side Panel 在目标尺寸下无按钮遮挡、文字溢出或不必要的横向滚动。

## 7. v0.4.0：对比、迁移与事务历史

实现状态：未开始。现有数据包导入已经具备“输入数据与当前站点”的新增、值变化、属性冲突、相同和不支持分类，也支持显式跨 origin 映射与最近一次批量导入的会话内撤销；这些属于 v0.4.0 的可复用基础，不代表快照、任意双源对比、选择性迁移和事务历史已经交付。

尚未完成：

- 可命名、复制、删除和导出的独立快照。
- 当前站点与快照、两个快照、两个标签页之间的对比工作流。
- JSON 结构化差异、Cookie value 与属性差异的独立对比视图。
- 面向目标标签页的选择性迁移和完全同步模式。
- transaction ID、事务摘要、逐项 before/after、整批与单项撤销。

### 7.1 目标

支持测试环境、UAT、生产环境或不同账号状态之间的差异分析与选择性迁移。

### 7.2 快照

- 从当前站点创建完整或部分快照。
- 快照记录来源、创建时间、数据范围和用户备注。
- 快照支持重命名、复制、删除和导出。
- Session Storage 快照明确标记其 tab 级语义，避免用户误认为会跨标签页自动同步。

### 7.3 差异对比

支持以下对比来源：

- 当前站点与保存的快照。
- 两个保存的快照。
- 当前窗口中的两个已授权 HTTP/HTTPS 标签页。

差异分类：

- 仅左侧存在。
- 仅右侧存在。
- 值不同。
- 属性不同。
- 完全相同。
- 当前浏览器不支持写入。

Cookie 的 value 差异和属性差异应分开显示。JSON 类型 value 优先使用结构化差异，普通字符串继续使用文本差异。

### 7.4 跨环境迁移

- 支持来源 host 到目标 host 的显式映射。
- Cookie domain 和 hostOnly 行为必须在预览中说明。
- 默认保持 path、flags 和 expiration 属性。
- 对无法应用的 Domain、Secure、SameSite、CHIPS 组合提前告警。
- 用户可选择只迁移值，或同时迁移允许修改的属性。
- 不允许在未预览的情况下直接执行完全同步。

### 7.5 事务历史

- 单条编辑、批量编辑、导入、配置组应用和迁移统一生成 transaction ID。
- 历史列表优先展示事务摘要，例如“修改 12 项，失败 1 项”。
- 事务详情展示每一项的 before、after、结果和错误。
- 支持撤销整个事务，也支持撤销事务中的单个项目。
- 完整值快照继续存放在 `chrome.storage.session`，浏览器会话结束后丢弃。
- 本地长期历史只保存元数据和大小等摘要，不长期保存完整敏感值。

### 7.6 验收标准

- 相同数据对比结果为空，不产生伪差异。
- Cookie value 与属性变化能分别识别。
- 用户可只选择部分差异应用到目标站点。
- 域名映射失败或浏览器拒绝属性组合时，在写入前或结果页明确说明。
- 一次批量迁移在历史中只占一个主记录。
- 整批撤销后，成功写入的项目恢复到操作前状态；撤销失败项目单独列出。

## 8. v0.5.0：完整编辑与安全

实现状态：未开始。当前列表可展示 HttpOnly、Secure、SameSite 和 Partitioned 等属性，编辑 value 或 expiration 时会尽量保留原 Cookie 属性，导入预览也会拦截部分明确无效的属性组合；高级属性编辑、敏感值统一保护和权限策略优化仍未实现。Manifest 当前仍使用全部 HTTP/HTTPS 站点权限。

### 8.1 Cookie 高级编辑器

基础模式保留当前 value 和 expiration 编辑体验，高级模式增加：

- Name。
- Domain 和 Host-only。
- Path。
- Session 或指定过期时间。
- SameSite。
- Secure。
- HttpOnly。
- Partitioned Cookie / CHIPS 可用属性。
- 浏览器 API 支持时展示 Priority 等附加属性。

保存前校验：

- `SameSite=None` 与 `Secure` 的组合。
- Domain 是否适用于目标 URL。
- Secure Cookie 是否使用 HTTPS。
- 过期时间是否有效。
- 重命名或修改作用域是否会创建新 Cookie 并保留旧 Cookie。
- Partitioned Cookie 是否具备有效 partitionKey。

修改 Name、Domain 或 Path 实际上可能产生新 Cookie。界面必须明确提示，并允许用户选择是否删除旧 Cookie。

### 8.2 敏感值保护

- 根据名称规则识别 `token`、`session`、`auth`、`jwt` 等疑似敏感项。
- 允许用户维护额外的敏感名称规则。
- 敏感值默认遮罩，点击后临时显示。
- 搜索默认不匹配被遮罩值，可由用户主动开启。
- 复制敏感值时提供非阻塞提示。
- 导出时提供“包含完整值”和“脱敏导出”两个明确选项。
- 配置组中的敏感值支持替换为应用时输入变量。

名称匹配只能作为风险提示，不能宣称已经识别所有敏感数据。

### 8.3 权限策略

对以下两种模式进行技术验证后确定最终方案：

1. 默认按站点申请权限，用户可主动开启全部站点权限。
2. 保留全部 HTTP/HTTPS 权限，但增加首次使用说明和当前站点访问状态。

推荐优先验证第一种模式。验收范围包括：

- Popup 首次打开当前站点。
- Side Panel 持续打开后切换页面。
- 当前窗口标签页切换。
- Cookie API 与 scripting API 的授权差异。
- 用户撤销权限后的降级和恢复流程。

### 8.4 验收标准

- 高级编辑可创建并正确修改常见 Cookie 属性。
- 浏览器不允许的属性组合在写入前给出可理解的提示。
- 修改 Cookie 标识字段时不会静默遗留旧 Cookie。
- 敏感值在列表、详情、历史和配置组中使用一致的遮罩规则。
- 脱敏导出不会包含原始敏感值。
- 权限不足、权限被撤销和特殊页面均有明确恢复入口。
- 隐私政策、商店权限说明和 Manifest 与最终权限方案保持一致。

## 12. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Chrome 拒绝 Cookie 属性组合 | 导入或迁移部分失败 | 写入前校验，逐项结果，保留 Chrome 原始错误 |
| 批量操作中途失败 | 目标状态不一致 | 操作前快照、事务记录、支持选择性回滚 |
| 跨环境 Domain 语义不同 | 创建错误 Cookie 或遗留旧 Cookie | 显式域名映射，预览最终作用域，不自动猜测删除 |
| 配置组保存敏感值 | 本机数据泄露风险 | 本地存储、遮罩、应用时输入变量、脱敏导出 |
| Session Storage 与 tab 绑定 | 快照恢复结果与预期不符 | 明确目标 tab，应用前提示，刷新后重新读取验证 |
| 全站权限降低用户信任 | 安装和商店审核受影响 | 验证按站点授权方案，权限说明与代码保持一致 |
| Popup 功能过密 | 小窗口难以使用 | Popup 保留高频操作，复杂预览和对比引导到 Side Panel |
| 数据量过大导致卡顿 | UI 无响应 | 分批执行、进度反馈、渲染分页或虚拟化 |

## 13. 开发前决策

以下事项在对应版本开始前确认，默认推荐项已注明：

1. 数据包主格式：版本化 JSON，推荐。
2. 批量导入默认策略：只新增和覆盖选中冲突，不删除额外数据，推荐。
3. 配置组存储位置：`chrome.storage.local`，推荐。
4. 敏感变量：支持应用时输入，不尝试无口令的伪加密，推荐。
5. 权限：优先验证按站点申请，可选开启全部站点，推荐。
6. 技术栈：继续使用原生 ES Module，先拆模块，不立即迁移 React，推荐。
7. 复杂工作流载体：Side Panel，Popup 保留快速操作，推荐。
